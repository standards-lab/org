# sqlate

`sqlate` is the SQL templating library, `github.com/standards-lab/sqlate`. This note is the
direction for the repository the `v1.data.sql.integration.sqlate` task creates. It was promoted
at the close of the `v1.data.sql.prototype` experiment on 2026-09-03. The experiment's record is
`experiments/sql-dsl/NOTES.md` and its verdict is `experiments/sql-dsl/REVIEW.md`. The code the
task moves is the experiment's `lib/` directory and `cmd/sqlint`, which already build without
go-database in their import graph. This is a concept: once the repository exists, its own
context takes the note over.

## The name

`sqlate` combines SQL and template. The library makes plain `.sql` files dynamic and composable
through templating instead of replacing them. Read aloud, the name is also "escalate": the
library extends what a `.sql` file can do.

The problem it addresses is that web services usually avoid real SQL. Queries are either
embedded as string literals in the host language or generated by an ORM. Both make the actual
query invisible and cut it off from SQL's own tooling: highlighting, linting, language servers,
and running `EXPLAIN ANALYZE` directly. `sqlate` keeps queries in first-class `.sql` files and
fixes their one real weakness, that they are static and repetitive.

The name drops the organization's `go-` prefix on purpose. `go-database` and `go-web-service` are
interdependent layers of one architecture, while `sqlate` is a standalone library that any Go
project can adopt on its own.

## What it is a pattern for

SQL is the first DSL in the architecture that needs this much support from the host language,
because SQL was not designed for the composition and portability the architecture requires. Not
every DSL will need it: a language designed to compose on its own needs no host-language
manipulation. For the ones that do, `sqlate` is the pattern to follow:

- a grammar the `.sql` files are written in;
- a host library that compiles and composes them;
- a catalog that makes the `.sql` infrastructure extensible: patterns and statements are
  sourced from multiple locations, each under its own namespace, and the compiler resolves
  includes against the catalog as a whole;
- engine sub-modules that own an engine's spellings;
- a lint that enforces the conventions.

The grammar is independent of Go. It is the first phase of the SQL meta language
(`docs/context/concepts/sql-meta-language.md`), and `sqlate` is its first host. Another host
implements the grammar, not the Go API.

## The grammar

An authored file is a header of `--|` declarations followed by the body. The engine receives the
body only.

```
--| tier: standard | native                 required
--| native: <the feature used and the port>  required when the tier is native
--| transaction: required                   optional: the statement refuses to run outside a transaction
--| key: <field>                            a projection base's identity column and sort tie-breaker
--| field: <name> <sql type>                one per field a request may filter or sort by
```

In the body:

- A parameter is `{{name}}`. Written `{{name:type}}`, it binds through `CAST` to an SQL type
  spelled as the engine reads it. Written `{{name...}}` or `{{name...:type}}`, it expands a
  non-empty list into one placeholder per element.
- An include, `{{> ns.name}}`, splices a pattern's text into the statement at compile time.
- A pattern is a SQL file the library or the application publishes under a namespace. It
  declares a tier, its body contains placeholders written `{{name}}`, and it never contains an
  include.

The delimiter is reserved. A `{{` that forms none of these is a load error, so the body needs no
lexer.

### sqlint.toml

`sqlint.toml`, one per module, configures the lint:

- One table per role (`statements`, `patterns`, `migrations`) lists the directory globs the role
  covers and the switches for its checks.
- A directory set that needs an exception overrides the role's switches in a table keyed by its
  quoted glob.
- `[sources]` maps each namespace to a path, and `engine` names a path.
- A producer is a Go package path, resolved through `go list`, or a directory with its own
  `sqlint.toml`. Its `[export]` table declares the directory it publishes, or an overlay
  directory, and its native forms.
- Native forms are regular expressions that serve as a deny list: a standard-tier `.sql` file
  that matches one fails the lint, and the finding is reported under the form's name.

## The packages

| Package | Contents |
|---|---|
| `sqlate` (root) | `Session`; `DB`, which wraps a plain `*sql.DB` through `Wrap`; `Tx`, `Begin`, `Transact`, `TxOption`; the `Dialect` interface (`Name`, `Placeholder`, `MapError`); `Locker`; `ErrorMapper`; the error types `ErrConnectionFailed`, `ErrInvalidValue`, and the constraint classes with `ConstraintError` |
| `sqlate/query` | the catalog (`Source`, `Publish`, `Patterns`, `As`, `Overlay`, `NewCatalog`, `Pattern`); `Compile`, which produces `Statements`; `Statement` with `Exec` and the methods `Scan`, `Project`, and `Guarded`, which produce `Rows[T]` (`One`, `All`, `Each`), `Projection[T]` (`List`, `One`, `Verify`), and `Guard` (`Run`); `Scanner[T]`, `Scalar[T]`, `ArgsOf`, and `Args.With`, which map columns and parameters to struct fields; `Directives`; `Verify`; `ErrDirectives` and its errors; `ErrVersionMismatch` |
| `sqlate/migrate` | `Migration`, `Files`, `Migrator` (`Version`, `Up`, `Down`, `Steps`, `Force`, `Verify`, `Migrations`), `Options`, `Catalog`, and the error types |
| `sqlate/internal/header` | the declaration grammar, shared by `query`, `migrate`, and `sqlint` |
| `sqlate/sqltest` | the scripted driver for unit tests: `Open`, `Recorder`, `Response`, and a stub `Dialect`. Public, because consumers' unit tests run over it |
| `sqlate/sqlint` | `Config`, `Load`, a `Resolver` over `go list`, `Lint(fs, cfg, resolver) []Finding`, one file per role's checks, and the glob matcher. `cmd/sqlint` handles arguments, the root directory, output, and the exit code |
| `sqlate/postgres` (sub-module) | the whole PostgreSQL dialect: placeholders, `MapError` with the constraint classes and class 22, `Locker` over advisory locks, and migrate's `Catalog`; its `sqlint.toml`; live tests over the driver. No overlay, because PostgreSQL is the standard spelling |

Two operations produce statements, compile and compose, and one consumes them, execute. The full
list of terms is the vocabulary section of the experiment's `NOTES.md`, headed Ontology.

## Placement

`sqlate` imports only the standard library, so it sits beside go-core in the workspace order,
and go-database is its first consumer. The methods that produce `Rows[T]`, `Projection[T]`, and
`Guard` are Go 1.27 generic methods on `Statement` and `DB`, so the library requires Go 1.27
from the start.

## Assumptions to check at creation

- The root package name `sqlate` collides with nothing, and every file also imports
  `database/sql`.
- The constraint classes move in from go-database together with `MapError`. go-database's own
  retire in v0.4.0, the task after this one.
- The live tests need the driver; the sub-module carries it, as go-database/postgres does.
