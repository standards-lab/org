# sqlate

The SQL templating library, `github.com/standards-lab/sqlate`: the direction for the
repository the `v1.data.sql.integration.sqlate` task creates, promoted at the close of the
`v1.data.sql.prototype` experiment (2026-09-03). The evidence is the experiment's record,
`experiments/sql-dsl/NOTES.md`, and its verdict, `experiments/sql-dsl/REVIEW.md`; the code
the task moves is the experiment's `lib/` and `cmd/sqlint`, which build with go-database
absent from their import graph. This is a concept: the repository's own context takes it
over once the repository exists.

## The name

`sqlate` is a portmanteau of SQL and template: it makes plain `.sql` files dynamic and
compositional through templating, rather than abandoning them. Read aloud, the name is also
"escalate"; the library escalates what a `.sql` file is capable of. The motivating problem
is that web services traditionally avoid real SQL: queries are either embedded as string
literals in the host language or generated by an ORM, and both make the actual query
invisible and cut it off from SQL's own tooling (highlighting, linting, LSPs, direct
`EXPLAIN ANALYZE`). `sqlate` keeps queries in first-class `.sql` files and addresses their
one legitimate weakness, that they are static and repetitive. It deliberately drops the
organization's `go-` prefix: `go-database` and `go-web-service` are interdependent layers of
an architecture, while `sqlate` is a standalone, independently adoptable library.

## What it is a blueprint for

SQL is the first DSL in the architecture to need this degree of host-language support,
because SQL was not designed for the composition and portability the architecture requires.
Not every DSL will: one designed to compose on its own operates independently of any
host-language manipulation. For the ones that do, `sqlate` is the pattern: a grammar the
files carry, a host library that compiles and composes them, engine sub-modules that own an
engine's spellings, and a lint that holds the conventions. The grammar is language
independent and is the first phase of the SQL meta language
(`docs/context/concepts/sql-meta-language.md`); `sqlate` is its first host, in Go, and
another host implements the grammar, not the Go API.

## The grammar

An authored file is a header of `--|` **declarations** followed by the body, which is what
the engine receives:

```
--| tier: standard | native        required
--| native: <the reach and the port>  required when the tier is native
--| transaction: required          optional: the runner refuses a session outside a transaction
--| key: <field>                   a projection base's identity and sort tie-breaker
--| field: <name> <sql type>       one per contract field; the only names a request may filter or sort by
```

In the body, a **parameter** is `{{name}}`, `{{name:type}}` to bind through `CAST` to an
SQL type written as the engine reads it, or `{{name...}}` and `{{name...:type}}` to expand a
non-empty list into one placeholder per element. An **include**, `{{> ns.name}}`, splices a
pattern's text at compile. A **pattern** is protocol SQL published under a namespace, a
file with a tier whose body holds **slots**, `{{name}}`, and never an include. The
delimiter is reserved: a `{{` that forms none of these is a load error, and the body needs
no lexer.

`sqlint.toml`, one per module, configures the lint: a table per role (`statements`,
`patterns`, `migrations`) with directory globs and check switches, an override table per
directory set under its quoted glob, `[sources]` mapping each namespace to a path and
`engine` a path, where a producer (a Go package path resolved through `go list`, or a
directory holding its own `sqlint.toml`) declares in `[export]` the directory it publishes
or the overlay directory and the native forms it names, each native form a regular
expression under the name a finding reports.

## The layout

| Package | Holds |
|---|---|
| `sqlate` | `Session`, `DB` over a plain `*sql.DB` with `Wrap`, `Tx`, `Begin`, `Transact`, `TxOption`, `Dialect` (`Name`, `Placeholder`, `MapError`), `Locker`, `ErrorMapper`; the error taxonomy: `ErrConnectionFailed`, `ErrInvalidValue`, the constraint classes with `ConstraintError` |
| `sqlate/query` | the catalog (`Source`, `Publish`, `Patterns`, `As`, `Overlay`, `NewCatalog`, `Pattern`), `Compile` to `Statements`, `Statement` with `Exec` and the handle methods `Scan`, `Project`, `Guarded`, `Rows[T]` (`One`, `All`, `Each`), `Projection[T]` (`List`, `One`, `Verify`), `Guard.Run`, the mapper (`Scanner[T]`, `Scalar[T]`, `ArgsOf`, `Args.With`), `Directives`, `Verify`, `ErrDirectives` and its errors, `ErrVersionMismatch` |
| `sqlate/migrate` | `Migration`, `Files`, `Migrator` (`Version`, `Up`, `Down`, `Steps`, `Force`, `Verify`, `Migrations`), `Options`, `Catalog`, the error types |
| `sqlate/internal/header` | the declaration grammar, shared by `query`, `migrate`, and `sqlint` |
| `sqlate/sqltest` | the strict scripted driver: `Open`, `Recorder`, `Response`, the stub `Dialect`; public, since consumers' hermetic tests run over it |
| `sqlate/sqlint` | `Config`, `Load`, a `Resolver` over `go list`, `Lint(fs, cfg, resolver) []Finding`, one file per role's checks, the glob matcher; `cmd/sqlint` is arguments, root, output, exit code |
| `sqlate/postgres` (sub-module) | the dialect entire: placeholders, `MapError` with the constraint classes and class 22, `Locker` over advisory locks, migrate's `Catalog`; its `sqlint.toml`; live tests over the driver. No overlay: PostgreSQL is the standard spelling |

Two acts produce statements, compile and compose; one consumes them, execute. The
vocabulary in full is the Ontology section of the experiment's `NOTES.md`.

## Placement

`sqlate` imports the standard library alone, so it sits beside go-core in the workspace
order, with go-database its first consumer. The handle constructors are Go 1.27 generic
methods on `Statement` and `DB`; the library is built on 1.27 from the start.

## Assumptions to check at creation

- The root package name `sqlate` collides with nothing; every file also imports
  `database/sql`.
- The constraint classes move in from go-database with `MapError`; go-database's own retire
  in v0.4.0, the task after this one.
- The live tests need the driver; the sub-module carries it, as go-database/postgres does.
